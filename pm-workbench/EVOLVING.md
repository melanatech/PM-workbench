## Design principles (stable — these are *why*, not just *what*)

1. **Retrieve, don't recompute.** If a source system already calculated a number, Claude logs it — never re-derives it. (`okr-refresh`.)
2. **Registers are the connective tissue, not command output.** Every command that produces a decision, a piece of evidence, or a stage change writes to a shared register (`registers/*.csv`, `registers/initiatives.csv`) — that's what lets other commands notice it later. See CONNECTIONS.md.
3. **Isolate for two reasons only: bias, or bulk.** Subagents exist either because a review needs to NOT see the thing it's reviewing was written by (the reviewer panels), or because a read is heavy enough that it shouldn't linger in the main session (context-gathering agents). Don't add a subagent just because a step exists — see AGENTS.md's "deliberately left as plain commands" list for the counter-examples.
4. **Never send/submit/write externally without approval, every time, no exceptions** — even in scheduled/headless runs, enforced structurally via `.claude/settings.json`'s permission scoping, not just as an instruction that could be forgotten.
5. **Say "not ready" out loud.** Readiness/drift/adversarial gates (`prd-package`, `launch-package`, `experiment-package`) are allowed to produce "this isn't ready yet, here's what's missing" as a valid, useful output — resist the urge to make every command always produce a polished final artifact regardless of input quality.
6. **Append, never overwrite, for anything that's a record of what happened.** Registers, `learning/`, `outputs/` history. Rotate into `archive/` when large; never silently restructure the past.

## Recipe: adding a new command

Ask, in order:
1. **Does it need multiple contextual sources?** → give it (or reuse) a context-gathering subagent (see `prd-context-gatherer`, `internal-docs-reader` for the pattern).
2. **Does a genuinely different stakeholder perspective matter, not just more detail?** → a reviewer subagent, isolated from the others (see the five PRD/prototype/experiment reviewers).
3. **Does it produce something another command should be able to find later?** → write to a register, and if it's about a specific feature, update `registers/initiatives.csv`.
4. **Does something else already tracked relate to this?** → add a cross-check against `registers/initiatives.csv` (and whichever other registers are relevant) before finalizing, the way `/discovery` and `/meeting-closeout` do.
5. **Does it write anything external (Jira, email, a form)?** → draft only, require explicit approval, and if it'll ever run headlessly, make sure `.claude/settings.json` denies the write action by default.
6. Add it to CLAUDE.md's command menu table and START HERE's duty table so it's discoverable both by name and by plain-language description.

## Recipe: changing something structural

Update AGENTS.md if it changes which steps are isolated and why. Update CONNECTIONS.md if it changes what reads or writes a register. Add a dated entry below. Don't silently let CLAUDE.md's standing rules and this file's design principles drift apart — if you change one, check whether the other needs to match.
